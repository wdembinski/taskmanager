## Decisions
- **Agent version.** The flow log ships in the next agent minor above whatever `main` has when step 1 starts: 0.4.0 if the throughput-report branch has not landed, 0.5.0 if it has. CONTRACT and code comments say "agent with flow log (§7 step 10)" rather than repeating a number in many places. `AGENT_VERSION` holds the actual number.
- **Verdict tags** stay exactly as `89d85f8` compiles them:
  - accept: `ct mark set 0x<rule id hex>`;
  - drop: a preceding `limit rate 10/second burst 20 packets log prefix "vipper-deny <rule id> " level info`;
  - mark 0 means unattributed (`rule: null`).
- **Agent guard** gets one extra quoted-string form: exactly `"vipper-deny (r_[0-9a-f]{8}|default) "`. Nothing else is loosened.
- **Sampling, each tick, after `policy_tick`.**
  - `conntrack -L -o extended,id` (binary `$CONNTRACK`, overridable by `VIPPER_CONNTRACK`).
  - Keep only entries whose original src is in the overlay CIDR.
  - From each entry take: `id`, proto, src, dst, dport (null for icmp), bytes (orig+reply), packets, mark → rule id (`r_%08x`, or null if 0), and `delta-time` if present → seconds.
  - Parse with one `jq -R -s` program. Drop malformed lines. Sort by bytes descending and cap at **250**.
- **Denied, each tick.**
  - `journalctl -k -o short-unix --grep '^vipper-deny ' --cursor-file "$WORK_DIR/kmsg.cursor"` (binary `$JOURNALCTL`, overridable by `VIPPER_JOURNALCTL`). On the first tick, start at `--since -2min`.
  - Parse the prefix rule id, `SRC=`, `DST=`, `PROTO=` and `DPT=`.
  - Aggregate by (rule, src, dst, proto, dport) into `{count, firstAt, lastAt}`. Cap at **100**, keeping the highest counts.
- **Tooling and kernel settings.**
  - cloud-init adds the package `conntrack` and sysctls `net.netfilter.nf_conntrack_acct=1` and `net.netfilter.nf_conntrack_timestamp=1`.
  - The agent also sets both sysctls at start (best effort), so existing VMs get bytes and durations without a re-create.
  - If the `conntrack` binary is missing, the agent warns once, sends `flows: []` and still sends the denied rows.
- **Report.**
  - `POST /relay/flows` with body `FlowReport = { bootId, sampledAt (ISO), flows: FlowSample[] ≤250, denied: DeniedSample[] ≤100 }`. It stays under the 64 kB limit; fields are terse.
  - `FlowSample = { ct: int, proto: 'tcp'|'udp'|'icmp'|<lowercase name ≤16>, src: IPv4, dst: IPv4, port: int 0..65535|null, bytes: int≥0, packets: int≥0, rule: /^r_[0-9a-f]{8}$/|null, seconds: int≥0|null }`.
  - `DeniedSample = { rule: /^r_[0-9a-f]{8}$|^default$/, src, dst, proto, port|null, count: int≥1, firstAt, lastAt }`.
  - The agent sends it every tick. A failure is only logged, as for `report_policy`.
- **Storage.** No new table, so no Terraform change.
  - Flows go in the `metrics` table, partition `fl:<hour ISO, e.g. 2026-10-25T13>`.
  - Accepted rows: RowKey `a_<bootId>_<ct>`, upserted with `firstSeen` kept from the existing row in that hour. `firstSeen` is otherwise `sampledAt − seconds`.
  - Denied rows: RowKey `d_<sha1(rule|src|dst|proto|port) first 16 hex>`, merged by adding the count and widening `firstAt`/`lastAt`.
  - Each row stores the resolved `srcDevice{id,name}`, `dstDevice{id,name}` at ingest, so names survive device deletion. The relay IP resolves to `relay`.
- **Retention and cap.**
  - The window is the last **24 h**: reads only cover `fl:` partitions for the last 24 hours.
  - Each ingest best-effort deletes rows of partitions 25–26 h old, at most once per hour per process.
  - Hard cap: **1,000 rows per hour partition**, counted in a `_count` row through the existing CAS loop. A new row beyond the cap is dropped and counted in `ignored`; updates to existing rows still apply.
  - Worst case is therefore 24,000 rows.
  - `POST /relay/flows` returns `200 { accepted, ignored }`.
- **Read API (admin).**
  - `GET /flows?device=&port=&rule=&result=&limit=` returns `200 { flows: Flow[], total, denied }`. `total` and `denied` count all matches in the 24 h window before `limit`, which feeds the footer "6 of 212 · 41 denied".
  - Filters:
    - `device` is a device id that matches src or dst;
    - `port` is an integer from 0 to 65535;
    - `rule` is `r_xxxxxxxx` or `default`;
    - `result` is `allowed` or `denied`;
    - `limit` is an integer from 1 to 1000, default 100.
    - Anything else is `400 validation_failed`.
  - Merge rows of the same key across hour partitions, keeping the latest. Sort by `lastSeen` descending.
  - `Flow = { id, result: 'allowed'|'denied', live: boolean (allowed and lastSeen == latest sampledAt), src:{ip,deviceId|null,name|null}, dst:{…}, proto, port, bytes|null, packets|null, durationSeconds, ruleId|null, ruleNumber|null, ruleComment|null, count (denied hits; 1 for allowed), firstSeen, lastSeen }`.
  - `ruleNumber` and `ruleComment` come from the active policy version's rules by id, at read time.
- **CSV.** `GET /flows/export?<same filters>` returns `200 text/csv; charset=utf-8` with `Content-Disposition: attachment; filename="flows-<ISO date>.csv"`.
  - Rows are all matches, up to the cap.
  - Header: `last_seen,first_seen,result,src_ip,src_device,dst_ip,dst_device,proto,port,bytes,packets,duration_s,rule_id,rule_number,rule_comment,count`.
  - Values follow RFC 4180 quoting. A field starting with `= + - @` is prefixed with `'`.
  - CORS exposes `Content-Disposition`.
