## Decisions

1. **Storage:** partition `"network"` in the existing `devices` table, RowKey = network id; props `name, cidr, isolated, note, isDefault, createdAt, createdBy, updatedAt`. No Terraform change.
2. **Seeding:** env `NETWORKS` becomes the **seed**: when the partition is empty, the API inserts the env networks (`createEntity`, 409 ignored; first = `isDefault`, `isolated:false`, `note:""`). After that the table is authoritative; env is still parsed and validated at startup. `NetworksService.list()` is async with an in-process cache invalidated on every write (TTL 30 s; max 1 replica).
3. **Network wire type** `Network { id; name; cidr; isolated; note; default; deviceCount; poolSize; createdAt }`. `id` `^[a-z0-9-]{1,32}$`, immutable (policy references `net:<id>`); `POST` takes `{id?, name, cidr?, isolated?, note?}` — `id` defaults to the name normalised like device labels and cut to 32; `name` 1..64 chars, no control chars; `note` ≤ 100; `cidr` defaults to next free. `PATCH /networks/:id` takes `{name?, note?, isolated?}`; `cidr` and `id` are immutable (`400` if sent).
4. **CIDR rules (POST):** valid IPv4 CIDR, prefix 24..30, inside `OVERLAY_CIDR`, not containing `RELAY_OVERLAY_IP`, not overlapping `10.88.0.0/24` (infrastructure/legacy) or any network → `409 network_overlap` naming the other network; id taken → `409 network_exists`. Race: insert, re-list, if an overlapping network sorts before ours (createdAt, id) delete ours and return `409 network_overlap`.
5. **Next free:** lowest `/24` in the overlay that overlaps no network and does not contain the relay IP (`10.88.0.0/24` is never offered); `null` when none. Returned as `nextFreeCidr` in `GET /networks`.
6. **DELETE:** `409 network_in_use` if it is the default network, holds any device or lease (incl. unbound reservations), or is referenced by `net:<id>` in the active version or the draft (message says which). Else `204`.
7. **Move a device:** `PUT /devices/:id/network {network, ip?}` (admin). `auto` device → lowest free address in the target network (stays `auto`); `ip` given → pinned there (`reserved`, lease reserved for owner+name); a `reserved` device without `ip` → `400 validation_failed` ("… has a reserved address; pass ip or release the reservation first"); same network → `200` no-op. Lease order: claim new → Merge device `{overlayIp, network, addressMode}` (new repo method) → release (or for reserved, delete) old lease; failure after claim releases the new lease. `forgetDevice(id)`. The moved client keeps its old IP until its service restarts or reloads — the mockup's "reconnect once"; pushing the change to the client is a follow-up, recorded in CONTRACT.
8. **`isolated` semantics (owner chose this, 2026-10-24):** "cut off unless a rule allows it". Published policies are already default-deny, so the compiler adds, **after** the user rules and before `counter drop comment "default"`, nothing new; but in the **v0 open policy** each isolated network gets `ip saddr @net_<id> drop` + `ip daddr @net_<id> drop` before `counter accept comment "default"` (no quoted comment; output unchanged when no network is isolated, so `open.nft` and relay `boot.nft` stay identical). The matrix shows isolated pairs as deny under v0. The mockup's "Open to core" posture is `isolated:false` **plus** copying every enabled rule that names `net:core` (with `net:core` → `net:<new>`) into the **draft** through the existing `GET /policy/draft` + `PUT /policy/draft` (If-Match), without publishing. That copy is console-side work in VPN-19 and needs no new API; write it into CONTRACT §3.4 under `POST /networks` as the intended client flow.
9. **Reachability** (`GET /networks/reachability`, admin): pure `evaluateReachability(rules, version, networks, devices)` in `policy/reachability.ts`, computed from the **active** version on every call. For each ordered pair (from, to) incl. the diagonal, walk enabled rules in order; a rule *applies* if its source can match an address in `from` and its destination one in `to` (`any` / `net:<that id>` = full; `tag:` / `device:` matching ≥ 1 enrolled device in that network = partial; no match = skip; unresolved = skip); protocol ≠ `any` or ports ≠ `any` = partial. First full-coverage rule terminates: allow → `allow` unless a partial deny was seen before (`partial`); deny → `deny` unless a partial allow was seen (`partial`). No terminator → default deny → `partial` if any partial allow was seen, else `deny`. v0 → `allow` everywhere except pairs touching an isolated network (`deny`). Response `{ version, networks: string[], cells: { from, to, state: 'allow'|'partial'|'deny', ruleIds: string[] }[] }` (`ruleIds` = applicable rules in order). (`ruleIds` is what lets VPN-19's "click a cell to edit its rules" list the cell's rules.)
10. **Audit:** `network.created` (`<id> <cidr>` + ` (isolated)`), `network.updated` (`<id>: isolated on|off, renamed "<a>" → "<b>", note`), `network.deleted` (`<id> <cidr>`), `device.moved` (`<name>: <from> → <to> (<ip>)`), all with the admin's sub, `subjectId` = network id / device id; no audit on no-ops.
11. **Pool size:** `poolSize` follows CONTRACT: a /24 has 253 device addresses (`.0`, `.1` and broadcast are reserved), not the mockup's 254.
